## 3. Подготовка и подключение ADB

Команды ниже предназначены для PowerShell из папки проекта. Утилита: `Инструменты\adb.exe`. Перед подключением включить ADB на самом проекторе.

### Включение ADB с пульта

1. Открыть настройки проектора и раздел «О проекторе» / «Об устройстве».
2. Выделить **имя проектора** и **нажать на него 7 раз** кнопкой подтверждения пульта. По сообщению владельца, именно так на проверенном устройстве открывается режим разработчика. Нажимать на имя, а не на номер сборки.
3. Открыть появившийся пункт **«Режим разработчика»** — в китайском интерфейсе **开发者模式**, в английском **Developer options**.
4. Найти **«Отладка ADB» / ADB debugging / ADB调试**, выбрать включение и подтвердить запрос. Раздел и привязка переключателя к `adb_enabled` подтверждены разбором штатного APK `AsuTvSettings`.
5. Подключить компьютер и проектор к одной локальной сети. Посмотреть текущий IP проектора в сведениях о сети.
6. На компьютере выполнить `adb connect IP_ПРОЕКТОРА:5555`. Если на проекторе появляется запрос разрешения отладки, подтвердить доступ своему компьютеру. Затем проверить `adb devices`: ожидаемый статус — `device`; `unauthorized` означает, что разрешение ещё не подтверждено.

Названия и расположение пунктов могут отличаться между прошивками и переводами. Последовательность «7 раз по имени» подтверждена владельцем; повторно скрытие и открытие режима в этой сессии не выполнялось. К началу установки прошивки ADB уже был включён и работал по TCP 5555.

Для этого Android 9 не требуется Android 11-функция сопряжения Wireless debugging с кодом. Если соединение не устанавливается, проверить IP, общую сеть, переключатель ADB и запрос авторизации. Команда `adb tcpip 5555` требует уже существующего ADB-соединения и не заменяет включение отладки с пульта.

ADB предоставляет доступ к устройству, а на 908 поддерживает root: использовать доверенную локальную сеть и не открывать порт 5555 в Интернет.

Общий справочник команд: [официальная документация Android Debug Bridge](https://developer.android.com/tools/adb). Путь меню Cronus выше основан на сообщении владельца и ресурсах APK, а не на стандартной инструкции для телефонов.

Последний подтверждённый адрес — 192.168.8.114. Ранее также использовался 192.168.1.83; адрес может меняться. Подставлять текущий IP во все команды.

```powershell
.\Инструменты\adb.exe connect 192.168.8.114:5555
.\Инструменты\adb.exe -s 192.168.8.114:5555 shell "getprop ro.product.device; getprop ro.build.internal.id; id"
Get-FileHash -Algorithm SHA256 -LiteralPath '.\Диагностика\Поиск-прошивки-2026-10-29\cronus-1.8.150-908-final-ota.zip'
```

Перед повторением на другом устройстве необходимо подтвердить модель, product/device и исходную сборку. Метод реально проверен для перехода 907 → 908. На уже обновлённом проекторе повторная установка для получения root не требуется.

## 4. Флешка и правильное имя файла

Нужен распознаваемый проектором USB-накопитель с запасом свободного места. Подготовленная флешка в нашей установке получила путь `/storage/3E47-1B1D`. Путь другого накопителя будет отличаться.

**Файл должен называться otaupdate.zip и находиться в корне флешки.** Переименование не меняет подпись и содержимое пакета.

Обнаруженная особенность штатного установщика: встроенный выбор файлов позволяет указать ZIP во внутренней памяти, но код затем игнорирует выбранный URI и читает `storagePath + /otaupdate.zip`. Без определённого съёмного накопителя возникла ошибка `null/otaupdate.zip`. Простого переименования во внутренней памяти недостаточно.

В выполненной процедуре сначала отправили исходный ZIP во внутреннюю память:

```powershell
.\Инструменты\adb.exe -s 192.168.8.114:5555 push '.\Диагностика\Поиск-прошивки-2026-10-29\cronus-1.8.150-908-final-ota.zip' /sdcard/Download/
.\Инструменты\adb.exe -s 192.168.8.114:5555 shell "sm list-volumes all; ls -l /storage; df -h"
```

Затем скопировали его на флешку. Перед командой проверить путь накопителя и отсутствие чужого `otaupdate.zip`, чтобы его не перезаписать.

```powershell
.\Инструменты\adb.exe -s 192.168.8.114:5555 shell "cp /sdcard/Download/cronus-1.8.150-908-final-ota.zip /storage/3E47-1B1D/otaupdate.zip && sync && md5sum /storage/3E47-1B1D/otaupdate.zip"
```

Ожидаемый MD5: `4ad7f0257269c6938ac3d1fc046203e5`. Дождаться окончания записи и проверки. Если сумма отличается, установку не запускать.

## 5. Запуск штатного обновления

Приложение `com.asu.osupdate` на нашем проекторе ранее было отключено. Его включили и открыли:

```powershell
.\Инструменты\adb.exe -s 192.168.8.114:5555 shell pm enable --user 0 com.asu.osupdate
.\Инструменты\adb.exe -s 192.168.8.114:5555 shell am start -n com.asu.osupdate/.UpdateMainActivity
```

На экране **System update** нажать **UPDATE**, предварительно проверив флешку и пакет. Не отключать питание и не вынимать накопитель до завершения. Не повторять нажатия во время копирования и проверки.

Ход проверки можно читать так:

```powershell
.\Инструменты\adb.exe -s 192.168.8.114:5555 shell "logcat -d -s OSUpdate:* RecoverySystem:*"
```

Фактически наблюдалась последовательность:

1. Обнаружение съёмного накопителя.
2. Копирование в `/data/user/0/com.asu.osupdate/files/update.zip`.
3. `verifyPackage progress 0 ... 100`.
4. `installPackage` и `REBOOTING TO INSTALL`.
5. Разрыв ADB при перезагрузке.
6. Возвращение рабочего стола и успешная проверка сборки 908.

Если ADB недоступен, это само по себе не доказывает сбой или успех. Проверить экран, дождаться загрузки и уточнить IP. При ошибке recovery записать точный текст; не выполнять сброс и не отключать питание вслепую.

## 6. Получение и проверка root

После загрузки рабочего стола:

```powershell
.\Инструменты\adb.exe connect 192.168.8.114:5555
.\Инструменты\adb.exe -s 192.168.8.114:5555 shell "getprop ro.build.internal.id; getprop ro.debuggable; id"
.\Инструменты\adb.exe -s 192.168.8.114:5555 root
.\Инструменты\adb.exe connect 192.168.8.114:5555
.\Инструменты\adb.exe -s 192.168.8.114:5555 shell "id; getenforce; command -v su"
```

Подтверждённый результат:

```text
cronus-1.8.150-908-final
ro.debuggable = 1
restarting adbd as root
uid=0(root) gid=0(root) ... context=u:r:su:s0
Enforcing
/system/xbin/su
```

Доказательство root — результат `id` с uid=0 после повторного подключения. Наличия строки userdebug или файла su недостаточно. После будущей перезагрузки проверить id заново; если ADB работает как shell, повторить adb root. Постоянство root через перезагрузку отдельно не проверялось.

Дополнительные файлы:

Для 24 разделов кроме userdata SHA-256 образа совпал с SHA-256 источника на проекторе. Архив userdata полностью прочитан с проверкой gzip; распакованный размер — **11882463232 байта**, совпадает с разделом. Он снимался при работающем Android, поэтому приложения могли изменять файлы во время чтения. Согласованность данных приложений не гарантируется.

Копия содержит персональные данные и потенциально ключи аккаунтов; хранить её приватно. Полезно перенести всю папку на отдельный накопитель и сверить SHA256SUMS.txt.

Скрипты в корне проекта: `backup_projector.py` и `verify_backup.py`. Это скрипты данной сессии с фиксированными IP и папкой назначения. Перед новой копией задать новую папку: существующий каталог автоматически безопасно не версионируется. Не запускать повторно без проверки этих параметров.

## 8. Что известно о восстановлении

Это проверенный набор образов разделов конкретного устройства. **Практическое восстановление на проектор не выполнялось.**

Для обратной записи потребуется подходящий доступ: работающий root, совместимое recovery либо подтверждённый сервисный режим. При повреждении загрузчика сначала понадобится восстановить доступ к устройству. Наличие файлов само по себе этого не обеспечивает.

Штатное recovery не подтверждено как средство установки этих образов. Они не являются подписанным OTA ZIP. Скачанный пакет 908 — отдельный подписанный OTA; его наличие также не означает, что recovery сможет восстановить любой тип повреждения.

Образа всей eMMC одним файлом нет; cache и промежутки между разделами не копировались. bootloader0/1 и mmcblk0boot0/1 имеют разные размеры и не должны подменяться друг другом. Заводские разделы и ключи нельзя переносить на другой проектор.

До восстановления требуется определить повреждённый раздел, состояние загрузчика/recovery, сверить карту разделов и подготовить конкретный способ обратной записи. Команды слепой прошивки здесь намеренно не приводятся: проверенного сценария восстановления пока нет.

На проверенном проекторе успешно выполнен переход с 907 на оригинальную 908, штатная проверка подписи прошла, рабочий стол загрузился, ADB root подтверждён командой id. Созданы и проверены образы разделов. Root для сторонних приложений, Magisk и процедура восстановления остаются непроверенными.
